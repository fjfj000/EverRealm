# 任务队列数据结构评审

> 状态：与时钟驱动任务系统最终方案对齐。  
> 关联：[游戏任务系统最终方案](游戏任务系统最终方案.md)

## 1. 评审结论

**时钟驱动 ≠ 全表扫描。**

- **时间源**只有 `WorldClock.TotalGameTime`，但时间推进权属于 `WorldDriver`；每次只推进到最近绝对 `nextSettleAt`、PauseWorld、日边界或目标。
- 两级直址表是 ScheduleIndex 优化：未来按滚动游戏日，今日按 `0..1439` 分钟；索引可由 TaskRecord 重建。
- `TaskSettleLevel` 只计算 cadence，不再让 `listen_min/hour/day/month/year` 分别执行任务。
- `TaskSequenceType` 只做分类和阶段排序；显式 `resourceClaims`、`dependsOn`、`serialKey` 才决定等待。
- ScheduleIndex、ReadyScheduler、ResourceArbiter 与三段 Gate 各自分责。

## 2. 推荐组件

```text
TaskRepository          // 权威 TaskRecord：状态、策略、nextSettleAt
FutureDayTable          // 对应 _tasks；unit = 滚动 epoch 下的游戏日
TodayMinuteTable        // 对应 _todayTasks；unit = 日内分钟
OverflowIndex           // 当前直址窗口外的未来 Task
ReadyScheduler          // deadline / priority / sequence
ResourceArbiter         // resourceClaims / serialKey
DependencyGraph         // dependsOn
ExecutionRepository     // executionId -> ExecutionRecord
DurableResultInbox      // 外部结果的持久化安全入口
SerialCommitQueue      // ChangeSet 单消费者队列
IdempotencyLedger       // 幂等键与 commitSequence
```

### 2.1 TaskRepository

- 持久化字段：`startTime`、`nextSettleAt`、deadline、`settleLevel`、`sequenceType`、`resourceClaims`、`dependsOn`、生命周期、priority、sequence、revision、ExecutionMode、TimePolicy 及过期/重入/恢复策略、payload。
- 不存：Promise、回调、运行时堆节点指针。
- Repository 是权威记录；两张直址表只保存可重建的调度引用。

### 2.2 FutureDayTable（`_tasks`）

- unit：`floor(nextSettleAt / GameTimeUnit.day)` 映射到滚动 epoch。
- 保存今天之后的 Task 下一结算点；不执行其中的 Task。
- WorldDriver 到达日边界时只读取新日槽并晋升到 TodayMinuteTable。
- 窗口长度由 360 日游戏年常量推导；窗口外数据进入 OverflowIndex，滚动时迁入，不能在第五年后抛越界。

### 2.3 TodayMinuteTable（`_todayTasks`）

- unit：`floor(gameTimeRemainder(nextSettleAt, "day") / GameTimeUnit.minute)`，有效范围 `0..1439`。
- 只有今日表能向 TaskPipeline 产出候选；未来槽不能执行。
- WorldDriver 只 drain 当前绝对边界命中的槽。不能 `for ... of _todayTasks`，否则会把稍后的 Task 提前执行。
- 同槽内按绝对 nextSettleAt、阶段、priority（数字小先）、持久化 sequence 排序。

今日表构造范围是 `0 .. GameTimeUnit.day / GameTimeUnit.minute - 1`。槽定位为 O(1)，但槽内数组 splice 仍是 O(m)，性能描述必须区分。

`_nextOccupiedSlot` 最坏扫描 `O(W/32)=O(W)`，不是渐进 O(1)。今日表 W=1440 时只有 45 个 word，五年日表约 57 个 word，实际成本很低；问题在于每次从 0 重扫。索引应维护 `minOccupiedSlot` 和单调 `scanCursor`，使整窗摊还扫描一次；更大窗口使用摘要位图或 occupied-slot heap。

### 2.4 Cadence、分类和互斥是三件事

- `TaskSettleLevel`：根据 StartTime 计算下一个绝对 nextSettleAt。
- `TaskSequenceType`：分类、阶段和默认排序，不是锁。
- `resourceClaims` / `serialKey`：真正的互斥范围。
- `dependsOn`：显式业务依赖。

长周期 Task 保持 Active，但只调度下一次 execution。Async Waiting 让出 ReadyScheduler；只有资源冲突请求进入 resourceWaiters。

### 2.5 ExecutionRepository

- 每一次触发创建独立 ExecutionRecord，支持同一 Task 的 Queue/Parallel。
- Ready、Running、Waiting、Prepared、Committing 等状态不再塞进单个 TaskRecord。
- PendingExecution 保存外部 correlationId、恢复策略与幂等键，不保存 Promise。
- 完成结果先持久化为 ResultCommand，安全点从 DurableResultInbox 按 commandSequence 回流 CommitGate。

### 2.6 SerialCommitQueue

- 单线程消费；保证 WorldState 变更顺序与验收 T01–T27 的哈希一致。
- Async 并行等待 ≠ 并行提交；提交临界区禁止 await。
- ChangeSet 必须携带 readSet/entityVersion；串行队列不能替代冲突检测。

## 3. 监听、晋升和执行算法

```text
WorldDriver.advanceTo(target):
  drain durable ResultInbox at safe point
  while clock.now < target:
    if boundary/time/execution budget exhausted:
      return Yielded(clock.now, target)

    nextTaskAt = scheduleIndex.peekNextDueAt()
    nextDayAt = nextGameDayBoundary(clock.now)
    boundary = min(target, nextTaskAt, nextDayAt)

    clock.moveTo(boundary) // 一次原子完成钟面状态

    if boundary == nextDayAt:
      promoteDay(absoluteDay(boundary))

    repeat until no same-time work:
      dueTasks = scheduleIndex.drainAt(boundary)
      requests = triggerGate.createRequests(dueTasks)
      readyScheduler.enqueueAll(requests)
      readyScheduler.startRunnable(resourceArbiter, dependencyGraph)

      if PauseWorld request activated or pendingDecision created:
        return partial(boundary)

      if sameTimeBudget exhausted:
        return Faulted(triggerChain)

ReadyScheduler.startRunnable:
  blocked requests -> resource/dependency waiters
  continue scanning for first runnable request
  never stop only because heap head is blocked
```

`listen_min/hour/day/month/year` 仅在 clock.moveTo 完成后发布派生通知，不参与权威排序。处理器异常必须隔离，不能中断钟面原子更新。

复杂度取决于跨过的有任务槽、命中数和槽内 m；位图可跳过空槽，但槽内有序数组插入仍为 O(m)。大跨度 advance 不能按每分钟扫描世界。核心 advanceSlice 同步返回 Completed / Paused / Yielded / AwaitingExternalInput / Faulted；异步 advanceFully 只负责跨帧续跑，不 await 业务 Promise。

## 4. 调度与有效性分离

| 层 | 只负责 | 不负责 |
| --- | --- | --- |
| ScheduleIndex / 两级直址表 | 插入、日切晋升、到期候选 | 谁先获得执行权、Task 是否仍有效 |
| ReadyScheduler | deadline、priority、sequence 与公平预算 | 时间索引、业务互斥 |
| ResourceArbiter / DependencyGraph | 资源读写冲突、serialKey、依赖与等待唤醒 | Task 分类和时间推进 |
| Trigger/Start/Commit Gate | 状态、deadline、revision、readSet/version、幂等 | 候选保存在哪个槽 |
| Executor | 调用同步处理器或启动异步工作 | 直接并发写 WorldState |
| SerialCommitQueue | 提交前复验、串行原子提交 | 等待 HTTP / 用户输入 |
| Finalizer | 更新状态、释放资源、唤醒 waiters、计算 nextSettleAt | 改动时钟 |

分离后的直接收益：

- Task 入表后被取消，不要求立即从所有索引中完美删除；出表时由 TriggerGate 安全丢弃。
- B 已进入 Ready 也不等于承诺执行；真正开始前由 StartGate 检查 startBefore 和资源。
- HTTP 结果迟到时走 CommitGate，不另写一套“异步合法性”。
- 队头 C/D 资源受阻时移入 waiters，ReadyScheduler 继续寻找不冲突的 B。
- ScheduleIndex 可独立做直址表性能测试；资源和业务规则测试不依赖表结构。

A 从 09:10 到 09:20 占用 `story:main`、B 在 09:12 使用不冲突资源启动、C/D 等待资源的完整时间线，见[游戏任务系统最终方案](游戏任务系统最终方案.md) §7.4。

## 5. 存档与重建

存档字段建议：

- `tasks: TaskRecord[]`
- `executions: ExecutionRecord[]`
- `worldClock.totalGameTime`
- 真实时间换算余数、commitSequence、idempotencyLedger
- 资源占用、依赖等待、未消费 ResultCommand 和 Async recovery/causality 元数据
- **不直接存** `_tasks` / `_todayTasks` 的位图与桶结构

读档后：

1. 重建 `TaskRepository`
2. 按 `nextSettleAt` 重建 `_tasks`、`_todayTasks`
3. 按 ExecutionRecord 重建 Ready、resource/dependency waiters 和 PendingExecution
4. 恢复 DurableResultInbox，先去重再按 commandSequence 消费
5. 按 RecoveryPolicy 重试、查询远端、取消或补偿外部异步
6. 恢复幂等账本与 commitSequence

WorldState、WorldClock、TaskRecord、ExecutionRecord、ResultInbox 和去重账本必须来自同一原子快照或日志事务，不能分别保存。

## 6. 评审检查清单

下列项已对照当前引擎和 `scripts/check-task-engine.ts` 核对。

- [x] Task 回调不直接给 `WorldClock` 加时间
- [x] RunningTicker 与 advance 都经过同一个 WorldDriver
- [x] target 跨 PauseWorld 时在写入目标前精确截断，并停到 `resumeAfterDecision`
- [x] 跨 Minute/Hour/Day 按绝对 nextSettleAt 排序
- [x] 日切和跨多日时先晋升再处理对应绝对边界
- [x] 今日表只 drain 当前绝对边界，不遍历未来 Task
- [x] 两级直址索引失效时能从 `nextSettleAt` 重建
- [x] 固定窗口外进入 overflow，滚动后能迁回
- [x] minOccupied/scanCursor 避免每次从槽 0 重扫；`activeUntil` 另做一次任务扫描
- [x] TaskSequenceType 不承担互斥语义
- [x] Ready 队头资源受阻时，后续不冲突请求继续
- [x] 多资源获取和依赖图无死锁；依赖成环返回 Faulted
- [x] 候选触发、真正开始、异步结果提交前都经过对应 Gate
- [x] ChangeSet 携带 readSet/entityVersion，并在提交时复验；冲突重算一次
- [x] Async 的超时、取消、中止和补偿会释放资源，并按 RecoveryPolicy 处理
- [x] ResultCommand 只经 durable inbox 在安全点消费
- [x] ContinueWorld 的因果依赖按 LatePolicy 处理；必须准时则用 StopWorldUntilResult
- [x] 边界预算返回 Yielded、同刻循环上限返回 Faulted
- [x] 存档覆盖 ExecutionRecord、ResultInbox、幂等账本、commitSequence、活动和暂停决定
- [x] 直址表 slot 范围与 `date-utils` 游戏日长度一致
