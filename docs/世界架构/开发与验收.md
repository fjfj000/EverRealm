# 文字沙盒战争游戏：世界系统开发与验收计划

## 1. 目标与范围

本阶段完成一个确定性、可回放的世界内核，以及内核外面的播放器。世界在游戏进行中按速率持续流逝。`advanceTo` 一次只激活当前检测区间里的任务；一天是最小检测间隔，长度可以配置。

先证明状态、时钟、队列、按天激活、活动和播放器可靠，再接入完整战斗、经济和战略 AI。

### 1.1 必须交付的能力

1. 创建、查询、修改和序列化世界状态。
2. 按到期时间、优先级和序号稳定调度事件。
3. 一次 `advanceTo` 只激活当前检测区间的任务。其他天的任务不在这次执行。
4. 从当前时间推进到目标时间，但不跨出当前区间；不重入。
5. 阻塞事件时停；非阻塞的限时事件继续走，超时后自动结束。
6. 多个活动并行，正确处理开始、结束、中断、取消和旧事件失效。
7. 连续量用锚点和整数余数结算，分段推进与一次推进结果相同。
8. 存档恢复、确定性回放和错误诊断。

### 1.2 模块职责

- **播放器**：把真实时间换成游戏分钟并调用 `advanceTo`。不管规则，不改世界状态。
- **世界时钟**：保存 `currentTime`。只有时间引擎可以把它向前拨。
- **时间引擎**：`advanceTo` 的循环。协调锚点结算、出队和提交。
- **事件队列**：保存未来的精确事件和下一次当日检测。
- **活动管理器**：管理活动的创建、暂停、恢复、完成和取消。
- **变更入口**：校验并一次性提交实体、索引、日志和新事件。

播放器不是第二套时钟。活动管理器也不是。队列不能自己拨动 `currentTime`。

## 2. 核心设计决策

| 设计项 | 决定 |
| --- | --- |
| 游戏时间 | 内部整数分钟。显示层再换成小时和日期 |
| 真实时间 | 播放器按速率换算。默认 1 真实秒 = 100 游戏秒 |
| 推进入口 | `advanceTo(targetTime)`。只处理当前区间内、且不晚于目标的事件 |
| 重入 | 正在执行时再次调用，直接拒绝 |
| 时停 | 只有阻塞事件暂停游戏时间。普通界面不暂停 |
| 检测间隔 | `taskIntervalMinutes`，默认 1440，可配置。这就是“一天” |
| 激活范围 | 只激活 `floor(dueTime / 间隔) == floor(currentTime / 间隔)` 的任务 |
| 其他天 | 更早的天出队并跳过；更晚的天留在队列，本次不激活 |
| 精确事件 | 抵达、离开、断粮、战斗阶段、阻塞决定、紧急评估。只在所属的那一天激活 |
| 同一分钟 | 连续状态 → 精确事件 → 当日检测 |
| 优先级 | 数字小的先执行。同优先级再用递增 `sequence` |
| 连续状态 | 锚点加整数余数。速率只在事件处改变 |
| 粮食 | 只按锚点扣除。当日检测不扣同一份粮 |
| 持续任务 | 活动表保存生命周期，队列保存未来时间点 |
| 取消 | 活动版本号加一。旧事件对不上就跳过 |
| 状态修改 | 处理器返回变更集，引擎一次性提交 |
| 随机数 | 多条可恢复的流。调用顺序跟着事件顺序走 |
| 存档 | 版本化 DTO。不直接序列化 `Map` 和堆 |
| 架构 | 单进程模块化单体 |

## 4. 播放器

``` ts
interface SessionPlayer {
  setRate(gameSecondsPerRealSecond: number): void;
  onRealTimeElapsed(realSeconds: number): AdvanceResult | null;
  onResume(elapsedRealSeconds: number): AdvanceResult;
}
```

`onRealTimeElapsed` 把真实秒数乘上速率，积成游戏分钟后再调用 `advanceTo`。换算余数留在播放器里，不进世界状态。

以下情况本次不调用 `advanceTo`：

- 上一次 `advanceTo` 还没返回。
- 世界正停在阻塞决定上。
- 速率为 0。玩家主动暂停用速率 0，和阻塞时停是两件事。

回到前台或离线补时时，播放器按积下的游戏分钟逐次调用 `advanceTo`。每一次只过完当前这一天。碰到阻塞事件就停在那一分钟，后面的天先不算。

回放记录游戏分钟上的命令，不记录帧间隔和速率。

## 5. 时间引擎

### 5.1 接口

``` ts
interface WorldDriver {
  advanceTo(targetTime: GameTime): AdvanceResult;
}

interface AdvanceResult {
  fromTime: GameTime;
  toTime: GameTime;
  processedEvents: number;
  skippedEvents: number;
  interrupted: boolean;
  pendingDecisionId?: EntityId;
}
```

`interrupted` 表示停在阻塞事件上。`toTime` 是实际到达的游戏分钟。它不会晚于当前检测区间的结束，也不能报成区间之外的目标时间。

当前区间是：

``` text
interval = taskIntervalMinutes
dayStart = floor(currentTime / interval) * interval
dayEnd = dayStart + interval
```

默认 `interval` 为 1440。改这个值就是改“一天”有多长。

### 5.2 推进循环

``` text
advanceTo(targetTime)
    │
    ├─ 正在执行，或已有未处理的阻塞决定 → 拒绝
    ├─ targetTime < currentTime → 拒绝，状态不变
    ├─ 本次终点 = min(targetTime, dayEnd)
    │
    └─ 循环，直到超过单次事件上限
           ├─ 看队列里最早的事件
           ├─ 没有事件，或它的天晚于今天，或它晚于本次终点
           │      └─ 锚点结算到本次终点，返回
           ├─ 它的天早于今天，或到期分钟已经早于 currentTime
           │      └─ 出队并跳过，不改状态
           ├─ 锚点结算到事件时刻，拨动时钟
           ├─ 版本不符或活动已终结 → 跳过
           ├─ 计算变更集并一次性提交
           ├─ 阻塞事件 → 记下决定，立即返回
           └─ 非阻塞事件 → 继续循环
```

同一分钟新提交的事件，只有仍属于今天、并且不晚于本次终点，才在本轮继续处理。处理器不能调用 `advanceTo`。玩家命令等本次返回后再提交。

阻塞事件提交之后，今天里优先级更低的事件留在队列里，游戏时间停在这一分钟。

单次推进要有事件上限。达到上限时停在当前分钟并报错，避免零延迟事件死循环。

### 5.3 优先级

| 优先级 | 事件 |
| --- | --- |
| 100 | 断粮和其他已经算出发火分钟的阈值 |
| 110 | 阻塞决定 |
| 120 | 抵达、离开、训练完成等活动节点 |
| 130 | 战斗阶段结束 |
| 140 | 紧急战略评估。每个势力同时最多一个 |
| 200 | 当日检测 `DAY_TICK` |

`sequence` 只在优先级相同的时候保序。探测和刷新内部按实体 ID 升序遍历。

### 5.4 为什么不会把以后的英雄提前做掉，也不会漏掉那一天

第 15 天遇见英雄 A，并排上第 35 天的离开。这次 `advanceTo` 的区间还是第 15 天，第 35 天的离开留在队列里，不激活。播放器要再调用 20 次，才会一天天走到第 35 天。

第 25 天的当日检测才决定英雄 B 出现，并排上第 26 天的离开。第 26 天的那次调用才激活这件离开。离开事件只结束这一次拜访。

停留短于 `taskIntervalMinutes` 的事，要到下一次当日检测才被看见。把间隔调小，检测就更密。

能用整数速度算出来、并且落在今天的相遇，仍排成精确事件。改道时作废旧预测。当日检测见到已经在进行的拜访时不要再建一次。

## 6. 当日检测

新游戏和读档之后，队列里必须有下一次 `DAY_TICK`，到期时间是某个区间的起点。执行完立刻排下一个区间的起点。加载时恢复这条事件，不能再创建一条。

| 任务 | 何时激活 | 做什么 | 不做什么 |
| --- | --- | --- | --- |
| 当日检测 | 区间起点，优先级 200 | 城镇生产、税收、军饷、英雄是否出现、无法预测的相遇、常规战略评估 | 不扣行军粮食，不激活其他天的任务 |
| 精确事件 | 到期分钟落在今天 | 处理该事件声明的那一件事 | 不把时间拨到明天 |

常规战略评估写在当日检测里。临时情报用优先级 140 的紧急评估，每个势力只保留一条；新的触发只改到期时间和原因。评估如果改变路线，只把新的行军事件排进队列。新事件若不属于今天，留到那一天再激活。

## 7. 活动

### 7.1 生命周期

``` text
创建活动
    ├─ 校验参与者和资源
    ├─ 注册活动，版本号从 1 开始
    └─ 安排第一个精确事件，或等它所在的那一天被检测到
           │
           ▼
       执行中
           ├─ 精确事件推进活动
           ├─ 暂停、取消或改计划 → 版本号加一
           └─ 结束条件成立 → completed / failed / cancelled
```

终态是 `completed`、`failed`、`cancelled`。进入终态时记录原因，结算一次，作废关联事件，并写诊断日志。重复进入终态不能再次发奖、扣资源或改变归属。

### 7.2 首批活动

| 活动 | 特点 | 验收重点 |
| --- | --- | --- |
| 行军 | 按下一节点排抵达，可能被遭遇打断 | 改道后旧抵达失效；位置只在节点事件提交时更新 |
| 围城 | 当日检测时结算，结束时间不固定 | 易主或撤退后，后续结算失效 |
| 训练 | 固定时长 | 到期只完成一次；取消后不再加经验 |
| 英雄拜访 | 非阻塞。出现时排离开事件 | 玩家不理他，离开到期后拜访结束；提前搭话则离开事件失效 |

行军进度放在行军活动上：当前路段、路段锚点和整数速度。队伍上的 `locationId` 只表示当前节点，不另存一份行军计划。

英雄拜访本身不阻塞。玩家点开一次被标成阻塞的对话时，才进入时停。

## 8. 连续状态

``` ts
interface AnchoredQuantity {
  value: number;
  remainder: number;
  anchoredAt: GameTime;
  rateNumerator: number;
  rateDenominator: number;
}
```

从锚点结算到目标分钟：

``` text
步数 = rateNumerator * (toTime - anchoredAt) + remainder
新的数量 = value - floor(步数 / rateDenominator)
新的余数 = 步数 mod rateDenominator
锚点改为 toTime
```

余数写入实体和存档。这样先推进 50 分钟、再推进 50 分钟，和一次推进 100 分钟得到同一结果。

速率变化时先结算到当前分钟，再改速率。断粮时刻若落在今天，排成优先级 100 的精确事件；若落在以后的天，留在队列里，等那一天再激活。

两个停靠点之间不要按分钟扫描全世界。挂机 20 天是播放器连着调用 20 次 `advanceTo`，每次只跑那一天的检测和当天的精确事件。

## 9. 变更集

处理器根据事件计算出要修改的实体、索引、日志和后续事件。引擎校验通过后一次性提交。校验失败或处理器抛错时，这次事件的修改全部不进入世界；该事件的失败政策要明确，不能只扣了一半资源。

世界时间在提交前可以停在事件分钟上，但实体保持提交前的值。阻塞决定作为这次提交的一部分写入 `pendingDecision`。

## 10. 存档、恢复与回放

至少保存：

- 当前游戏分钟、`taskIntervalMinutes`、规则版本、存档版本。
- 权威实体、活动、锚点余数。
- 各随机流的完整状态。
- 下一实体序号、下一事件序号。
- 待处理事件，包括下一次当日检测。
- 未完成的阻塞决定。

不要既保存事件，又在加载时无条件按活动再建一套。加载后要核对：进行中的行军有下一次节点事件，进行中的拜访有离开事件，当日检测恰好还有一条未来事件。

确定性对照：

- A：连续推进到第 10 天。
- B：分成多段推进到第 10 天。
- C：推进到第 5 天，保存、加载，再推进到第 10 天。

三种结果的权威状态一致。比较前按实体 ID 排序，忽略日志里的墙钟时间。

## 12. 验收清单

| 验收项 | 通过标准 |
| --- | --- |
| 事件顺序 | 与独立参考排序器一致。优先级数字小的先执行 |
| 时间边界 | 今天内 `dueTime == targetTime` 的有效事件会执行。目标落在明天时，本次停在今天结束 |
| 禁止倒退 | 目标早于当前时间时拒绝，状态不变 |
| 重入 | 执行中再次调用被拒绝，外层状态不被嵌套推进 |
| 只激活当天 | 第 15 天调用时，第 35 天的离开仍在队列中且未执行。走到第 25 天时当日检测仍会执行 |
| 英雄拜访 | 非阻塞。离开前搭话则旧离开失效；不理则到期结束一次 |
| 阻塞 | 返回实际分钟；更低优先级的同刻事件留在队列；游戏时间停止 |
| 离线补时 | 遇到阻塞即停止，不把后面的时间结算掉 |
| 连续状态 | 任意分段方式与一次推进的数量和余数相同 |
| 粮食 | 当日检测之后，行军粮食只减少锚点扣除的那一份 |
| 终结幂等 | 重复结束不重复扣费、发奖或易主 |
| 过期任务 | 早于今天，或今天里已经早于 `currentTime` 的任务被跳过，世界继续 |
| 存档 | 不产生第二条当日检测。`taskIntervalMinutes` 能原样恢复 |
| 确定性 | A、B、C 三种推进的权威状态一致 |
| 长跑 | 365 个游戏日无负数、无重复结算、无事件死循环 |

长跑的起点规模：100 支军队、50 个城镇、500 个活动，并随机取消、改道和结束。这是测试起点，不是最终世界规模。

性能先记录 `advanceTo` 的耗时、队列长度和 365 天总时间。在这个规模下使用三键堆，按配置的一天逐次推进，不引入时间轮。

**最终原则：播放器决定真实时间怎么流，一次推进只激活当前这一天，精确事件在它自己的那一天生效，时间引擎提交变化，活动保存生命周期。**
