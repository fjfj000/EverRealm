# 文字沙盒战争游戏：世界系统开发与验收计划

## 1. 目标与范围

本阶段完成一个确定性、可回放的世界内核，以及内核外面的播放器。世界在游戏进行中由**时钟**按速率持续流逝；Task 系统对每段 `(fromGameTime, toGameTime]` 做结算。在线 Tick 与 `advance`（挂机/离线/快进）**共用同一结算引擎**。日检测是最常见的 cadence，间隔默认 1440 游戏分钟，可配置。

先证明状态、时钟、区间结算、索引、活动和播放器可靠，再接入完整战斗、经济和战略 AI。

### 1.1 必须交付的能力

1. 创建、查询、修改和序列化世界状态。
2. 按到期时间、优先级和序号稳定调度事件。
3. 在线 Tick 与 advance 共用 WorldDriver，按绝对 `nextSettleAt`、日边界和 PauseWorld 逐点推进，不跨过未处理边界。
4. TaskSequenceType 只分类；显式资源/依赖决定等待。ReadyScheduler 必须旁路资源受阻队头。
5. Async Waiting 让出调度器；只有 PauseWorld 暂停时间。deadline 拆分为 startBefore、commitBefore、activeUntil。
6. 多个活动并行，正确处理开始、结束、中断、取消和旧事件失效。
7. 连续量用锚点和整数余数结算，分段推进与一次推进结果相同。
8. 存档恢复、确定性回放和错误诊断。

### 1.2 模块职责

- **播放器**：提交真实增量或离线目标，不直接改 WorldClock。
- **世界时钟**：保存整数 `TotalGameTime`，由 WorldDriver 原子 moveTo；分级事件仅作派生通知。
- **WorldDriver**：在线 Tick 与 advance 的唯一边界推进器。
- **TaskManager**：维护 TaskRepository、ExecutionRepository 和两级 ScheduleIndex，生成到期 execution。
- **执行仲裁**：ReadyScheduler、ResourceArbiter、DependencyGraph 和三段 Gate。
- **活动管理器**：管理活动的创建、暂停、恢复、完成和取消。
- **变更入口**：校验并一次性提交实体、索引、日志和新事件。

播放器不是第二套时钟。活动管理器也不是。队列不能自己拨动 `currentTime`。

## 2. 核心设计决策

| 设计项 | 决定 |
| --- | --- |
| 游戏时间 | 权威单位是累计游戏秒；Task 最低结算粒度是分钟。显示层再换成小时和日期 |
| 真实时间 | 播放器按速率换算。默认 1 真实秒 = 100 游戏秒 |
| 日常推进 | RunningTicker → WorldDriver → 最近绝对边界 → WorldClock.moveTo |
| 补时/快进 | `advance(targetTime)`，复用同一边界循环 |
| 重入 | 正在执行区间结算时再次进入，直接拒绝 |
| 时停 | 仅 PauseWorld（或玩家速率 0）；时钟不得先越过再回退 |
| 检测间隔 | `taskIntervalMinutes`，默认 1440。日检测 Task 的 cadence 参考值 |
| cadence | TaskSettleLevel 只计算 nextSettleAt；权威顺序统一按绝对时间 |
| 精确事件 | 抵达、离开、断粮、战斗阶段、阻塞决定、紧急评估。只在所属的那一天激活 |
| 同一分钟 | 连续状态 → 精确事件 → 当日检测 |
| 优先级 | 数字小的先执行。同优先级再用递增 `sequence` |
| 连续状态 | 锚点加整数余数。速率只在事件处改变 |
| 粮食 | 只按锚点扣除。当日检测不扣同一份粮 |
| 持续任务 | 活动表保存生命周期，队列保存未来时间点 |
| 取消 | 活动版本号加一。旧事件对不上就跳过 |
| 状态修改 | 处理器返回带 readSet/entityVersion 的 ChangeSet，CommitGate 复验后原子提交 |
| 随机数 | 多条可恢复的流。调用顺序跟着事件顺序走 |
| 存档 | 版本化 DTO。不直接序列化 `Map`、直址表位图和运行时 Promise |
| 架构 | 单进程模块化单体 |

## 4. 播放器

``` ts
interface SessionPlayer {
  setRate(gameSecondsPerRealSecond: number): void;
  onRealTimeElapsed(realSeconds: number): AdvanceResult | null;
  onResume(elapsedRealSeconds: number): AdvanceResult;
}
```

在线：`onRealTimeElapsed` 把真实秒交给 WorldDriver。Driver 使用当前倍速与持久化余数计算 target，再逐个推进绝对边界。换算余数属于时间系统并写入存档，不进业务 Task。

以下情况本次不推进游戏时间或不调用 `advance`：

- 上一次区间结算还没返回（重入拒绝）。
- 世界因 **PauseWorld** 停在未完成的决定上（advance 路径）。
- 速率为 0。玩家主动暂停与 PauseWorld 是两件事。

回到前台或离线补时时，播放器调用 `advance(target)` 追赶；共用 Tick 的结算引擎。遇到 PauseWorld 边界即停住并返回，剩余 target 待玩家处理后再 advance。

回放记录游戏分钟上的命令，不记录帧间隔和速率。

## 5. 时间引擎

### 5.1 接口

``` ts
interface WorldDriver {
  /** 同步处理一个预算切片；不等待业务 Promise。 */
  advanceSlice(
    targetTime: GameTime,
    budget: AdvanceBudget
  ): AdvanceResult;
}

type AdvanceStatus =
  | "completed"
  | "paused"
  | "yielded"
  | "awaitingExternalInput"
  | "faulted";

interface AdvanceResult {
  status: AdvanceStatus;
  fromTime: GameTime;
  toTime: GameTime;
  targetTime: GameTime;
  processedBoundaries: number;
  processedExecutions: number;
  sameTimeRounds: number;
  pendingDecisionId?: EntityId;
  faultReason?: string;
}
```

`advanceFully()` 可作为异步包装，在 `yielded` 时 `await nextFrame()` 后续跑；它不能 await HTTP/用户 Task。边界/execution/毫秒预算是正常分帧机制；同刻轮数/执行数上限是死循环保护，超限返回 `faulted`。

### 5.2 统一绝对边界循环与 TaskPipeline

``` text
WorldDriver.advanceTo(target)
    └─ while now < target
         ├─ boundary = min(target, nextSettleAt, nextDayBoundary)
         ├─ WorldClock.moveTo(boundary)
         ├─ 日边界：先晋升未来表
         ├─ drainAt(boundary) -> TriggerGate -> TaskExecutionRequest
         ├─ ReadyScheduler
         │    ├─ 资源/依赖受阻 -> waiters，继续扫描
         │    └─ 可运行 -> StartGate -> Executor
         ├─ Async -> PendingExecution 并让出调度器
         ├─ CommitGate(readSet/version) -> SerialCommitQueue
         ├─ Finalizer -> 释放资源、唤醒 waiters、重排
         ├─ 同刻新 Task 处理到 fixpoint
         └─ PauseWorld -> partial return
```

`listen_*` 只在 moveTo 原子完成后通知 UI/派生系统。TaskSequenceType 不承担锁语义；互斥使用 resourceClaims/serialKey，依赖使用 dependsOn。单次推进和同刻 fixpoint 都必须有预算，超限输出循环链诊断。

Promise 完成只写 DurableResultInbox；在 boundary batch 之后的安全点按 commandSequence 消费 ResultCommand。ContinueWorld 下若 15 分 Task dependsOn 12 分 HTTP，而结果 16 分才回流，该 Task 必须按 startLatePolicy 处理，不能倒退。必须准时发生时使用 StopWorldUntilResult / PauseWorld。

### 5.3 优先级

| 优先级 | 事件 |
| --- | --- |
| 100 | 断粮和其他已经算出发火分钟的阈值 |
| 110 | 阻塞决定 |
| 120 | 抵达、离开、训练完成等活动节点 |
| 130 | 战斗阶段结束 |
| 140 | 紧急战略评估。每个势力同时最多一个 |
| 200 | 当日检测 `DAY_TICK` |

`sequence` 只在优先级相同的时候保序。探测和刷新内部按实体 ID 升序遍历。

### 5.4 为什么不会把以后的英雄提前做掉，也不会漏掉结算

第 15 天遇见英雄 A，并排上第 35 天的离开边界。在 `(from, to]` 仅覆盖第 15 天时，第 35 天的边界不在区间内，**不会**被结算。时钟继续到第 35 天时，该边界进入区间并被处理。

第 25 天的日检测才决定英雄 B 出现，并排上第 26 天的离开。第 26 日对应的 `(from, to]` 才结算 B 的离开。离开只结束这一次拜访。

**长周期 A 与短窗口 B**：A 在 20 天内保持 Active 并按 cadence 结算，**不**占全局执行器；B 在自身 `[Start, End)` 内独立激活与过期（验收 T03）。

停留短于 `taskIntervalMinutes` 的事，要到下一次日检测才被看见。把间隔调小，检测就更密。

能用整数速度算出来的相遇，仍排成精确边界 Task。改道时作废旧 revision。日检测见到已在进行的拜访时不要再建一次。

## 6. 当日检测

新游戏和读档之后，队列里必须有下一次 `DAY_TICK`，到期时间是某个区间的起点。执行完立刻排下一个区间的起点。加载时恢复这条事件，不能再创建一条。

| 任务 | 何时激活 | 做什么 | 不做什么 |
| --- | --- | --- | --- |
| 日检测 | cadence 边界，优先级 200 | 城镇生产、税收、军饷、英雄是否出现、无法预测的相遇、常规战略评估 | 不扣行军粮食 |
| 精确边界 | `dueTime ∈ (from, to]` | 处理该边界声明的那一件事 | 不反向拨时钟 |

常规战略评估写在日检测里。临时情报用优先级 140 的紧急评估，每个势力只保留一条。评估如果改变路线，只注册新的行军边界；边界时刻未到则留待对应区间结算。

## 7. 活动

### 7.1 生命周期

``` text
创建活动
    ├─ 校验参与者和资源
    ├─ 注册活动，版本号从 1 开始
    └─ 安排第一个精确事件，或等它所在的那一天被检测到
           │
           ▼
       执行中
           ├─ 精确事件推进活动
           ├─ 暂停、取消或改计划 → 版本号加一
           └─ 结束条件成立 → completed / failed / cancelled
```

终态是 `completed`、`failed`、`cancelled`。进入终态时记录原因，结算一次，作废关联事件，并写诊断日志。重复进入终态不能再次发奖、扣资源或改变归属。

### 7.2 首批活动

| 活动 | 特点 | 验收重点 |
| --- | --- | --- |
| 行军 | 按下一节点排抵达，可能被遭遇打断 | 改道后旧抵达失效；位置只在节点事件提交时更新 |
| 围城 | 当日检测时结算，结束时间不固定 | 易主或撤退后，后续结算失效 |
| 训练 | 固定时长 | 到期只完成一次；取消后不再加经验 |
| 英雄拜访 | 非阻塞。出现时排离开事件 | 玩家不理他，离开到期后拜访结束；提前搭话则离开事件失效 |

行军进度放在行军活动上：当前路段、路段锚点和整数速度。队伍上的 `locationId` 只表示当前节点，不另存一份行军计划。

英雄拜访本身不阻塞。玩家点开一次被标成阻塞的对话时，才进入时停。

## 8. 连续状态

``` ts
interface AnchoredQuantity {
  value: number;
  remainder: number;
  anchoredAt: GameTime;
  rateNumerator: number;
  rateDenominator: number;
}
```

从锚点结算到目标分钟：

``` text
步数 = rateNumerator * (toTime - anchoredAt) + remainder
新的数量 = value - floor(步数 / rateDenominator)
新的余数 = 步数 mod rateDenominator
锚点改为 toTime
```

余数写入实体和存档。这样先推进 50 分钟、再推进 50 分钟，和一次推进 100 分钟得到同一结果。

速率变化时先结算到当前分钟，再改速率。断粮时刻若落在今天，排成优先级 100 的精确事件；若落在以后的天，留在队列里，等那一天再激活。

两个停靠点之间不要按分钟扫描全世界。挂机 20 天可以是一次 `advance` 跨多段 `(from, to]`，或 Tick 持续累加；结果须与分段 advance 的权威状态一致（验收 T02）。

## 9. 变更集

处理器根据事件计算出要修改的实体、索引、日志和后续事件。引擎校验通过后一次性提交。校验失败或处理器抛错时，这次事件的修改全部不进入世界；该事件的失败政策要明确，不能只扣了一半资源。

世界时间在提交前可以停在事件分钟上，但实体保持提交前的值。阻塞决定作为这次提交的一部分写入 `pendingDecision`。

## 10. 存档、恢复与回放

至少保存：

- 当前游戏分钟、`taskIntervalMinutes`、规则版本、存档版本。
- 权威实体、活动、锚点余数。
- 各随机流的完整状态。
- 下一实体序号、下一事件序号。
- 待处理事件，包括下一次当日检测。
- 未完成的阻塞决定。

不要既保存事件，又在加载时无条件按活动再建一套。加载后要核对：进行中的行军有下一次节点事件，进行中的拜访有离开事件，当日检测恰好还有一条未来事件。

确定性对照：

- A：连续推进到第 10 天。
- B：分成多段推进到第 10 天。
- C：推进到第 5 天，保存、加载，再推进到第 10 天。

三种结果的权威状态一致。比较前按实体 ID 排序，忽略日志里的墙钟时间。

## 12. 验收清单

| 验收项 | 通过标准 |
| --- | --- |
| Task 顺序 | 与独立参考排序器一致。统一 priority 方向；完全同键由持久化 sequence 保序 |
| 时间边界 | `(from, to]` 内所有有效边界按序结算；advance 在 PauseWorld 处提前返回 |
| 禁止倒退 | 目标早于当前时间时拒绝，状态不变 |
| 重入 | 执行中再次调用被拒绝，外层状态不被嵌套推进 |
| 长/短 Task 共存 | A Active 20 天期间，B 在自身 2 天窗口内激活、结算、过期，不被 A 吞噬 |
| 英雄拜访 | 非阻塞。离开前搭话则旧离开失效；不理则到期结束一次 |
| PauseWorld | advance 返回实际 `toTime`；游戏时间停止直至决定完成 |
| Waiting 非时停 | A Waiting 让出调度器；C/D 因资源冲突等待；无冲突 B 在有效窗口启动 |
| 离线补时 | 遇到 PauseWorld 即停止 advance，不把其后时间一次性结算掉 |
| 连续状态 | 任意分段方式与一次推进的数量和余数相同 |
| 粮食 | 当日检测之后，行军粮食只减少锚点扣除的那一份 |
| 终结幂等 | 重复结束不重复扣费、发奖或易主 |
| 过期任务 | 早于今天，或今天里已经早于 `currentTime` 的任务被跳过，世界继续 |
| 存档 | World/Clock/Task/Execution/幂等账本来自同一原子快照 |
| 确定性 | 纯确定性任务或已录制外部输入的 A、B、C 推进状态一致 |
| 长跑 | 365 个游戏日无负数、无重复结算、无事件死循环 |
| 挂机 advance | 对纯确定性/录制回放，一次 advance 与分段推进哈希一致（对照 T02） |
| 异步重入 | 同一 Active Task 在 Waiting 时下一 cadence 边界到达，行为符合 OverlapPolicy（对照 T07） |
| HTTP 迟到 | revision/version 变化或幂等键已提交时结果不入库（对照 T16） |
| 读档 | ExecutionRecord、资源等待、幂等账本和 ScheduleIndex 无损恢复（对照 T09） |
| 多单位跨越 | 单次 Tick 跨分钟/小时/日时按绝对边界全序处理（对照 T01、T11） |
| 调度/有效性分离 | 已入表 Task 被取消或 revision 改变后，由对应 Gate 跳过（对照 T13） |
| 当前槽隔离 | 10:00 只 drain 10:00；11:00 与明日 Task 不提前执行（对照 T14） |
| 防吞噬 | C/D 资源受阻时旁路队头，无冲突 B 继续（对照 T04、T15） |
| 异步恢复 | timeout/Abort/finally/recoveryPolicy 不永久占资源（对照 T16、T17） |
| 时钟原子性 | 派生监听器抛错不破坏钟面和权威推进（对照 T18） |
| 资源语义 | Task 类型不决定互斥；同实体写冲突受保护（对照 T19） |
| 长期运行 | 超出固定窗口后 overflow/epoch 正常迁移（对照 T20） |
| 整数时间 | 不同 realDelta 分段得到相同边界（对照 T21） |
| 非法重排 | dueAt≤now 按策略处理且不无限循环（对照 T22） |
| 因果异步 | ContinueWorld 下依赖任务迟到；StopWorld 下准时恢复（对照 T23、T24） |
| ResultCommand | durable inbox、幂等去重和崩溃恢复（对照 T25） |
| 推进预算 | 边界预算 Yielded；同刻死循环 Faulted（对照 T26） |
| 位图扫描 | scanCursor 避免每次从 0 重扫（对照 T27） |

任务系统验收矩阵 T01–T27 见 `docs/评审文档/任务系统/游戏任务系统最终方案.md` §13。

长跑的起点规模：100 支军队、50 个城镇、500 个活动，并随机取消、改道和结束。这是测试起点，不是最终世界规模。

性能记录边界数、总表/今日表/overflow 命中、资源等待、槽内 m、TaskPipeline 各阶段耗时与 365 游戏日总时间。区分槽定位 O(1) 与槽内插入 O(m)。

**最终原则：WorldDriver 按绝对边界推进；TaskSequenceType 只分类；资源/依赖决定等待；Async 让出调度器；版本化提交串行；只有 PauseWorld 停时钟。**
