# 世界驱动架构

## 1. 目标

本游戏是参考《骑马与砍杀》的文字沙盒。敌方 AI 由程序实现，不依赖 LLM。世界在玩家游玩时持续流逝，包括挂机积累资源。一天是最小检测间隔，长度可配置。`advanceTo` 一次只激活这一天的任务。

规范的推进循环以 `开发与验收.md` 为准。本文说明模块边界。

## 2. 两层结构

``` text
真实时间
    |
    v
播放器 SessionPlayer
  速率换算、主动暂停、离线补时
  阻塞时停止调用
    |
    v
时间引擎 WorldDriver.advanceTo
  + 世界时钟 WorldClock
  + 事件队列 EventQueue
  + 锚点结算 ContinuousUpdater
  + 活动管理器 ActivityManager
  + 事件分发 EventDispatcher
    |
    v
变更入口
    |
    v
WorldState + 索引 + 日志 + 存档
```

- **播放器**：默认 1 真实秒 = 100 游戏秒。速率放在播放器上，不放进 `WorldState`。
- **世界时钟**：唯一的当前游戏分钟。禁止业务模块私自拨动。
- **时间引擎**：唯一的推进入口。正在执行时拒绝再次进入。
- **事件队列**：保存精确事件和下一次当日检测。一次推进只出今天的任务。
- **锚点结算**：在两个停靠点之间推导粮食和行军，不按分钟扫描。
- **活动管理器**：行军、围城、训练、英雄拜访的生命周期。
- **NPC AI**：在当日检测或紧急评估里提出意图，不直接改状态，不调用 `advanceTo`。
- **变更入口**：校验后一次性提交。

## 3. 游戏进行时怎么流动

播放器每一拍把经过的真实秒数乘上速率，积满整数游戏分钟后调用 `advanceTo(当前分钟 + 新增分钟)`。

- 普通菜单、战报和未点开的英雄拜访：播放器继续走。
- 阻塞决定：播放器不再调用，真实时间可以继续，游戏分钟不动。玩家提交选择之后才恢复。
- 速率为 0：玩家主动暂停，效果同样是不再调用。
- 窗口被限流后回到前台：按积压的游戏分钟一天天调用 `advanceTo`。每一次只激活当天任务，补到阻塞事件就停。

命令在 `advanceTo` 返回之后提交。处理器如果需要世界继续走，只排新事件。

## 4. 队列里有什么

| 工作 | 怎么进队列 | 阻塞 |
| --- | --- | --- |
| 下一节点抵达 | 行军开始或改道时排精确事件 | 否 |
| 英雄离开 | 拜访开始时排精确事件 | 否 |
| 断粮 | 消耗速率变化时算出分钟并排精确事件 | 视规则而定 |
| 战斗阶段结束 | 阶段开始时按配置的世界分钟排精确事件 | 需要玩家选战术时是 |
| 当日检测 | 每个检测区间的起点保留下一次 | 否 |
| 紧急评估 | 每个势力最多一条 | 否 |

当日检测负责生产、税收、军饷、英雄刷新、无法预测的相遇和常规战略评估。行军粮食不在这次检测里再扣一次。不属于今天的精确事件，即使已经在队列里，这次也不激活。

第 15 天排了英雄 A 在第 35 天离开。第 15 天的调用会跳过这件离开，把它留在队列里。播放器走到第 25 天时，那一天的检测才可能刷新出英雄 B，并排上第 26 天的离开。第 26 天的调用才激活 B 的离开。

## 5. 推进时各模块做什么

1. 播放器或测试调用 `advanceTo(目标分钟)`。
2. 引擎拒绝重入、拒绝倒退、拒绝在未完成的阻塞决定上继续走。
3. 本次终点收束到当前检测区间的结束，不进入下一天。
4. 早于今天的事件出队并跳过，不改状态。晚于今天的事件留在队列里。
5. 今天内的事件才锚点结算到它的分钟，并拨动时钟。
6. 版本不符的事件跳过。
7. 分发器按类型调用处理器。处理器返回变更集。
8. 变更入口一次性提交。阻塞事件同时写下 `pendingDecision`，引擎立刻返回。
9. 非阻塞事件提交后，循环继续。新事件只有仍属于今天才在本轮执行。

同一分钟的优先级见 `开发与验收.md`：阈值、阻塞、活动节点、战斗阶段、紧急评估、当日检测。

## 6. 活动与行军

活动是持续任务的唯一记录。队伍的 `locationId` 是当前节点，行军路线和路段锚点放在行军活动里。

开始行军：

1. 校验状态、目的地和补给。
2. 创建行军活动。
3. 只排下一节点的抵达，不把全程合成一个终点事件。
4. 若这条边上的相遇分钟算得出来，另排一条精确遭遇，并在改道时作废。
5. 算不出来的相遇留给它所在那一天的当日检测。短于检测间隔的停留，要等下一次检测。

抵达提交后更新 `locationId`。若还有下一节点，排下一个抵达。遭遇若是非阻塞拜访，创建拜访活动并排离开事件。遭遇若需要玩家立即决定，排阻塞事件，播放器在那一分钟停下。

旧抵达靠活动版本失效。战后或对话结束后，由新的命令决定继续、改道或取消，再排新事件。

## 7. 英雄拜访

当日检测决定英雄出现时：

1. 创建非阻塞的拜访活动。
2. 排一条离开事件，到期分钟 = 当前分钟 + 停留分钟。
3. 播放器不时停。

玩家在离开前搭话：活动版本加一，离开事件到期后跳过，再按这次对话的规则决定是否阻塞。玩家一直不操作：离开事件结束拜访，只结算一次。

## 8. NPC 决策

战略评估放在当日检测里，按势力 ID 升序执行。临时情报使用紧急评估，每个势力同时只有一条。

AI 只接收 `Observation`，输出 `ActionProposal`。变更入口检查合法性后再修改状态。评估可以安排行军和以后的事件，不能拨时钟，也不能在处理器里调用 `advanceTo`。

目标切换需要分数差超过固定阈值，避免每一天来回改目的地。

## 9. 玩家命令

``` text
玩家输入
  -> PlayerCommand
  -> 若 advanceTo 正在执行，等它返回
  -> 校验
  -> 创建或修改活动，安排事件
  -> 播放器继续按速率推进
  -> 阻塞则等玩家选择
  -> 返回结果
```

读菜单不单独阻止时间。时间停，只因为有阻塞决定，或玩家把速率设成 0。

失败的命令不能留下半成品扣费。命令日志按游戏分钟记录，供回放；它和世界历史日志不是同一份。

## 10. 初始化与读档

新游戏：

1. 创建实体，记下实体序号。
2. 建立索引。
3. 排好下一次当日检测，间隔使用 `taskIntervalMinutes`。
4. 为已经在进行的活动排精确事件。
5. 创建时间引擎和播放器。

读档：

- 恢复实体、活动、锚点余数、当前分钟、检测间隔、随机流、序号、待处理事件、下一次当日检测和阻塞决定。
- 重建索引和事件堆。
- 核对当日检测没有重复，活动引用的事件仍然对得上版本。
- 不要无条件再排一条当日检测。

## 12. 开发顺序

1. `WorldState`、序号、随机流。
2. 三键事件队列。
3. `advanceTo`、按天激活和锚点结算。
4. 变更入口。
5. 行军、围城、训练、英雄拜访。
6. 播放器、阻塞时停和离线补时。
7. 存档与回放。
8. 战斗阶段、经济和战略 AI。

**最终原则：播放器让游戏时间跟着真实时间走，一次推进只激活当前这一天，精确事件在自己的那一天生效，时间引擎提交变化，AI 只提出意图。**
