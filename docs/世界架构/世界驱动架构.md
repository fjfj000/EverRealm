# 世界驱动架构

## 1. 目标

本游戏是参考《骑马与砍杀》的文字沙盒。敌方 AI 由程序实现，不依赖 LLM。世界在玩家游玩时**时钟持续流逝**；Task 系统对每段 `(from, to]` 结算。日检测是常见 cadence，间隔可配置。

规范的推进循环以 `开发与验收.md` 为准。Task 结算语义以 `docs/评审文档/任务系统/游戏任务系统最终方案.md` 为准。任务引擎已按该方案实现，检查脚本是 `scripts/check-task-engine.ts`。本文说明模块边界。

## 2. 两层结构

``` text
真实时间
    |
    v
播放器 SessionPlayer
  速率换算、主动暂停、离线 advance 补时
    |
    v
WorldDriver.tick(realDelta) / advance(target)
  计算目标时间
  查询 nextSettleAt / 日边界 / PauseWorld
    |
    v
WorldClock.moveTo(最近边界)
  原子更新时间后发布派生通知
    |
    v
TaskManager / TaskPipeline（+ 锚点 ContinuousUpdater）
  + TaskRepository / 两级 ScheduleIndex / Overflow
  + ReadyScheduler / ResourceArbiter / DependencyGraph
  + TriggerGate / StartGate / Executor / CommitGate / Finalizer
  + ExecutionRepository / IdempotencyLedger
  + SerialCommitQueue
  + 活动 revision 校验
    |
    v
变更入口
    |
    v
WorldState + 索引 + 日志 + 存档
```

- **播放器**：默认 1 真实秒 = 100 游戏秒。速率在播放器上，不放进 `WorldState`。
- **世界时钟**：权威整数 `TotalGameTime`；不决定下一个边界，不执行 Task。
- **WorldDriver**：在线 Tick 与 advance 的唯一推进器；时钟尚未越过 PauseWorld 时即可截断。
- **Task 索引**：未来日表、今日分钟表和 overflow；只按 nextSettleAt 产出候选。
- **TaskPipeline**：ReadyScheduler 不因队头资源冲突停止；ResourceArbiter/DependencyGraph 负责等待；所有 Task 共用三段 Gate 和提交器。
- **锚点结算**：在两个边界之间推导粮食和行军，不按分钟扫描全世界。
- **活动管理器**：行军、围城、训练、英雄拜访的生命周期与 revision。
- **NPC AI**：在日检测或紧急评估里提出意图，不直接改状态，不拨时钟。
- **变更入口**：校验后**串行**一次性提交。

## 3. 游戏进行时怎么流动

在线：播放器每一拍把真实增量交给 WorldDriver。Driver 计算目标游戏时间，并逐个处理最近 `nextSettleAt` / 日边界 / PauseWorld，最后才到本 Tick 目标。

- 普通菜单、战报和未点开的英雄拜访：时钟继续走，其他 Task 照常结算。
- **PauseWorld** 决定：WorldClock 尚未越过该时刻，Driver 返回 partial；玩家提交选择后继续剩余 target。
- 速率为 0：玩家主动暂停，不累加游戏时间。
- 离线补时：`advance(target)` 追赶，遇 PauseWorld 即返回。

命令在当前同步管线批次返回之后提交。处理器若需后续结算，只更新 `nextSettleAt`，由 Finalizer 重排；不能嵌套推进时钟。

## 4. 两级时间索引与执行仲裁

`_tasks` 是带滚动 epoch 的未来日表；`_todayTasks` 是 `0..1439` 今日分钟表；窗口外进入 overflow。它们都是可重建索引，权威记录在 TaskRepository。

`TaskSettleLevel` 只计算 cadence。到期 Task 生成 `TaskExecutionRequest`；TaskSequenceType 参与分类和排序，资源 claim、serialKey 与 dependsOn 决定互斥和等待。

Driver 不严格逐分钟：10→16 之间只有 12、15 两个边界时走 `10→12→15→16`；每分钟 Task 真实存在时才逐分钟。ScheduleIndex 用 minOccupied/scanCursor 避免每次从位图槽 0 重扫；位图最坏 `O(W/32)=O(W)`，固定 1440 分钟窗口实际最多 45 个 word。

| 工作 | 怎么进索引 | PauseWorld |
| --- | --- | --- |
| 下一节点抵达 | 行军开始或改道时排 settle 边界 | 否 |
| 英雄离开 | 拜访开始时排边界 | 否 |
| 断粮 | 速率变化时算出时刻并排边界 | 视规则 |
| 战斗阶段结束 | 阶段开始时按配置排边界 | 需玩家选战术时可能是 |
| 日检测 | cadence=Day 的 Task | 否 |
| 紧急评估 | 每个势力最多一条 | 否 |

日检测负责生产、税收、军饷、英雄刷新、无法预测的相遇和常规战略评估。行军粮食不在日检测里再扣一次。

长周期 Active Task（例如 20 天 buff）在 `[Start, End)` 内按 cadence 多次结算，**不会**用一个回调占满执行器从而吞掉短窗口 Task B。

## 5. 推进时各模块做什么

1. Tick 或 advance 向 WorldDriver 提交目标时间。
2. Driver 查询 ScheduleIndex 与下一日边界，选择最近绝对 boundary。
3. WorldClock 原子 moveTo(boundary)；若是日边界则先晋升新日槽。
4. ScheduleIndex.drainAt(boundary)，TriggerGate 生成 ExecutionRecord / TaskExecutionRequest。
5. ReadyScheduler 按 deadline、priority、sequence 选择；资源或依赖受阻项移入 waiters，继续寻找后续可运行请求。
6. StartGate 获取资源，Executor 同步返回或创建 PendingExecution；Async 让出调度器。
7. CommitGate 校验 deadline、revision、readSet/entityVersion 与幂等键；SerialCommitQueue 原子提交。
8. Finalizer 释放资源、唤醒 waiters、计算 nextSettleAt；同刻新 Task 处理到 fixpoint。
9. 若提交 PauseWorld，Driver 返回当前 boundary；否则继续到目标。

`listen_min/hour/day/month/year` 只在 moveTo 后发布派生通知；订阅者异常不能破坏钟面或权威 Task 顺序。

同一时刻的优先级见 `开发与验收.md`：阈值、PauseWorld 决定、活动节点、战斗阶段、紧急评估、日检测。

核心 `advanceSlice(target, budget)` 是同步函数，不 await 业务 Promise，返回 Completed / Paused / Yielded / AwaitingExternalInput / Faulted。`advanceFully()` 可以是 Promise 包装，但只在 Yielded 时 `await nextFrame()` 后续跑。

预算分两类：边界/execution/毫秒预算达到后正常 Yielded；同刻 fixpoint 轮数/执行数超限则 Faulted，并记录零延迟触发链。

Async 完成后只把 ResultCommand 写入 DurableResultInbox；当前 boundary batch 返回后的安全点再消费。若后续 Task dependsOn 该结果，ContinueWorld 可能让它超过 startBefore；必须按 LatePolicy 处理，或在异步发起点使用 StopWorldUntilResult。

## 6. 活动与行军

活动是持续任务的权威记录。队伍的 `locationId` 是当前节点，行军路线和路段锚点放在行军活动里。

开始行军：

1. 校验状态、目的地和补给。
2. 创建行军活动。
3. 只排下一节点的抵达边界，不把全程合成一个终点。
4. 若相遇分钟可算，另排精确遭遇；改道时作废旧 revision。
5. 算不出来的相遇留给日检测。短于检测间隔的停留，等下一次检测。

抵达提交后更新 `locationId`。若还有下一节点，排下一个抵达。遭遇若是非阻塞拜访，创建拜访活动并排离开边界。遭遇若需要玩家立即决定，使用 **PauseWorld** Task，advance 在该时刻停下。

## 7. 英雄拜访

日检测决定英雄出现时：

1. 创建非阻塞的拜访活动。
2. 排离开边界，到期 = 当前 + 停留。
3. 默认 **ContinueWorld**，时钟继续。

玩家在离开前搭话：revision 加一，旧离开跳过；对话若需 PauseWorld 则单独声明。玩家一直不操作：离开边界结束拜访，只结算一次。

## 8. NPC 决策

战略评估放在日检测里，按势力 ID 升序。临时情报用紧急评估，每个势力同时只有一条。

AI 只接收 `Observation`，输出 `ActionProposal`。变更入口检查合法性后再修改状态。评估可以安排新 Task 边界，不能拨时钟，不能在处理器里嵌套区间结算。

## 9. 玩家命令

``` text
玩家输入
  -> PlayerCommand
  -> 若区间结算正在执行，等它返回
  -> 校验
  -> 创建或修改活动，注册 Task 边界
  -> 播放器继续 Tick / advance
  -> PauseWorld 则等玩家选择
  -> 返回结果
```

读菜单不单独阻止时间。时间停，只因为 PauseWorld，或玩家把速率设成 0。

## 10. 初始化与读档

新游戏：创建实体、索引、日检测 Task、进行中活动的边界、WorldDriver 与播放器。

读档：从同一原子快照恢复实体、活动、锚点、`TotalGameTime`、TaskRecord、ExecutionRecord、资源/依赖等待、幂等账本与 commitSequence；按 `nextSettleAt` 重建总表、今日表和 overflow。

## 12. 开发顺序

1. `WorldState`、序号、随机流。
2. 修复整数时间、单例、ID/sequence、表范围与构造签名。
3. TaskRepository、ExecutionRecord 与两级 ScheduleIndex / overflow。
4. WorldDriver 统一 Tick/advance 的绝对边界推进。
5. TaskExecutionRequest、ReadyScheduler、ResourceArbiter、DependencyGraph、三段 Gate 与版本化提交。
6. 行军、围城、训练、英雄拜访。
7. Async RecoveryPolicy、原子存档与回放。
8. 战斗阶段、经济和战略 AI。

**最终原则：WorldDriver 按绝对边界推进；TaskSequenceType 不承担互斥；显式资源和依赖决定等待；Async 让出调度器；版本化提交全局串行；只有 PauseWorld 停时钟。**
